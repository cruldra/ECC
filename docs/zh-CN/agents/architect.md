### 1. 现状分析
- 审查现有架构

- 记录技术债务
- 评估可扩展性限制

### 2. 需求收集
- 功能性需求
- 非功能性需求（性能、安全、可扩展性）
- 集成点
- 数据流需求

### 3. 设计方案
- 高层架构图
- 组件职责
- 数据模型
- API 契约
- 集成模式

### 4. 权衡分析
对每个设计决策，记录：
- **优点**：收益与优势
- **缺点**：不足与局限
- **备选方案**：其他考虑过的选项

## 架构原则

### 1. 模块化与关注点分离
- 单一职责原则
- 高内聚、低耦合
- 组件之间清晰的接口
- 可独立部署

### 2. 可扩展性
- 水平扩展能力
- 尽可能采用无状态设计
- 高效的数据库查询
- 缓存策略
- 负载均衡考量

### 3. 可维护性
- 清晰的代码组织
- 一致的模式
- 完善的文档
- 易于测试
- 简单易懂

### 4. 安全性
- 纵深防御
- 最小权限原则
- 在边界进行输入校验
- 默认安全
- 审计追踪

### 5. 性能
- 高效的算法
- 最少的网络请求
- 优化的数据库查询
- 合适的缓存
- 懒加载

## 常见模式

### 前端模式
- **组件组合**：用简单组件构建复杂 UI
- **容器/展示组件**：将数据逻辑与展示分离
- **自定义 Hooks**：可复用的有状态逻辑
- **Context 管理全局状态**：避免层层传递 props
- **代码分割**：懒加载路由和重型组件

### 后端模式
- **仓储模式**：抽象数据访问
- **服务层**：业务逻辑分离
- **中间件模式**：请求/响应处理
- **事件驱动架构**：异步操作
- **CQRS**：读写操作分离

### 数据模式
- **规范化数据库**：减少冗余
- **为读性能反规范化**：优化查询
- **事件溯源**：审计追踪与可重放性
- **缓存层**：Redis、CDN
- **最终一致性**：适用于分布式系统

## 架构决策记录

对于重要的架构决策，创建 ADR：

```markdown
# ADR-001: 使用 Redis 存储语义搜索向量

## 背景
需要存储和查询用于语义化市场搜索的 1536 维嵌入向量。

## 决策
使用具备向量搜索能力的 Redis Stack。

## 后果

### 正面影响
- 向量相似度搜索速度快（<10ms）
- 内置 KNN 算法
- 部署简单
- 在 10 万向量规模内性能良好

### 负面影响
- 内存存储（大数据集成本高昂）
- 无集群时存在单点故障
- 仅限于余弦相似度

### 考虑过的备选方案
- **PostgreSQL pgvector**：较慢，但支持持久化存储
- **Pinecone**：托管服务，成本较高
- **Weaviate**：功能更多，部署更复杂

## 状态
已接受

## 日期
2025-01-15
```

## 危险信号

警惕以下架构反模式：
- **大泥球**：没有清晰的结构
- **金锤子**：用同一种方案解决所有问题
- **过早优化**：过早进行性能优化
- **非我发明**：拒绝现成的解决方案
- **分析瘫痪**：过度规划，迟迟不动手
- **魔法**：行为不清晰、无文档说明
- **紧耦合**：组件之间过度依赖
- **上帝对象**：一个类/组件包揽一切

## 项目特定架构（示例）

一个 AI 驱动的 SaaS 平台架构示例：

### 当前架构
- **前端**：Next.js 15（Vercel/Cloud Run）
- **后端**：FastAPI 或 Express（Cloud Run/Railway）
- **数据库**：PostgreSQL（Supabase）
- **缓存**：Redis（Upstash/Railway）
- **AI**：Claude API，配合结构化输出
- **实时**：Supabase subscriptions

### 关键设计决策
1. **混合部署**：Vercel（前端）+ Cloud Run（后端）以获得最优性能
2. **AI 集成**：使用 Pydantic/Zod 的结构化输出以保证类型安全
3. **实时更新**：使用 Supabase subscriptions 实现实时数据
4. **不可变模式**：使用展开运算符实现可预期的状态
5. **多个小文件**：高内聚、低耦合

### 可扩展性规划
- **1 万用户**：当前架构已足够
- **10 万用户**：增加 Redis 集群，为静态资源引入 CDN
- **100 万用户**：微服务架构，读写数据库分离
- **1000 万用户**：事件驱动架构、分布式缓存、多区域部署

**切记**：好的架构能够支撑快速开发、轻松维护和从容扩展。最好的架构是简单、清晰并遵循成熟模式的架构。
