# 3D 交互教程

一个主题一页，产出是一个自带全部脚本的 HTML，双击就能离线打开。页面分两种：

- **学习页**：想搞清楚一个项目（多半是开源项目）某一块的内部逻辑。像 Jupyter 笔记本一样从上到下讲完：文字格子、代码格子和 3D 动画格子穿插排列，带子主题。
- **改造页**：要在现有代码上修问题或做优化，现有机制可能被换掉。只有两节：现状、解决方案，各一段说明加一段 3D 演示。

| 页面 | 种类 | 主题 |
|---|---|---|
| `example.html` | 学习页 | 示例：拆分与合并 |
| `example-change.html` | 改造页 | 示例：次数表更新 |

## 页面结构

两种页面的标题下面都只放 `<h1>`，不放面包屑、副标题和写工单的那一行，紧跟着是目录。

**学习页**按顺序分成下面几节：

1. **简介**：它是什么、为什么需要它（存在的意义，比如模型只认数字、不认文字，所以要先分词），不单独再开一章讲动机。核心流程配一个 3D 演示，演示正下方紧跟一个配套的代码格子，用项目的代码跑演示里的同一个例子（In / Out 用真实运行结果）。
2. **核心概念**：一张 3D 概念图，列出学这个主题要接触的全部核心概念和它们之间的关系（谁产出谁、谁用到谁）。第 1 步看全貌，之后按章节顺序一块块点亮，并链到讲它的那一章；每一章在图里都有一步，新增一章就补一步。
3. **每个核心概念一章**：概念图上的每个概念各占一个二级标题（简介已经讲过的输入和输出除外）。同类的变体（ByteLevel、Metaspace、Whitespace）各占一个三级标题；概念分好几类时（特殊 token），章开头先写简介，再用列表讲各类，每类举一个官方例子。主流做法的原理（比如 BPE 怎么训练、怎么编码）是它所属那一章下的一个三级标题，不单独占一章。同一章下的同类条目（比如四种算法）用同一个模板、同一种演示布局（后排训练、前排编码），章末不加对比小节。

- 讲某种变体（算法、预分词器、解码器）的三级标题按这个顺序写：通用简介（它是什么、从哪来并链论文、为什么有用、在库里对应哪个类，不围着当前项目写）→ `<p><b>使用场景</b></p>` 列表（只写名字加链接，当前项目链源码，外部项目链明确写着它用了这个做法的官方页面，链接前打开页面搜一下做法的名字）→ 一个演示，原理写进各步说明。不写讲原理的列表和注释框，旁枝内容留给讲它的那一节；演示后面和最后一步说明重复的段落删掉。讲机制而不是讲变体的三级标题（整段认出、聊天模板）不写使用场景列表。
- 讲怎么运作的内容不写成代码格子、要点列表、注释框、键值表或 SVG 结构图，一律放进演示说明。
- 讲第三方库（被讲解的项目依赖的库，比如 tokenizers）的一章固定是「简介 → 组件地图 → 各组件或文件的小节」：简介之后紧跟一张组件地图，不加小标题和引出的话；其它章节没讲到的文件和组件（tokenizer.json）各一节，用演示讲它怎么来、怎么用。组件地图讲这个库怎么拆（类、模块、哪些必须哪些可选、编码、训练、解码各走哪条路），和讲领域概念的概念图分开。旧式的「SVG 结构图 + 读组件的代码格子 + 组件卡片」不再用。
- 本项目没用到的库组件，用一个用到它的官方模型（如 `bert-base-uncased`）真实跑出数据，说明里写明用的哪个模型。
- 使用场景的证据可以是一份写明每个模型用什么的官方源码，比如 HF transformers 的 `convert_slow_tokenizer.py`（BertConverter 用 BertPreTokenizer 和 WordPiece，GPT2、Roberta、Qwen2 用 ByteLevel，SpmConverter 用 Metaspace），列表里几项共用这一个链接。
- 不写名义上讲动机、实际在比较各种做法的章节；做法之间的不同（按字节、按整词、按子词）由各个做法自己的条目讲。
- 删章节时，找出被删内容里第一次出现并带链接的词；后文再出现的地方现在是首次出现，补上链接。
- 讲机制的每一节、每一点都要有 3D 演示（数据进去变了样出来、几个部件互相作用），只有文字或两条列表项不算讲清楚。
- 二级、三级标题都会进左侧目录，三级标题缩进在所属的二级标题下面。

**改造页**只有两节，不放代码格子、表格、卡片和子主题：

1. **现状**（`<h2 id="now">`）：一段话说现在怎么运作、哪里出问题，再放一段组件图演示，数据取自一次真实运行，问题标成 `gap`。
2. **解决方案**（`<h2 id="next">`）：一段话说改了什么、为什么能解决，再放一段组件图演示，数据取自设计文档。

两段演示各用一张图（`GRAPH_NOW`、`GRAPH_NEXT`）：两张图里都有的组件 `id` 和位置一样，去掉的组件不放进方案图，新的或改过的用 `new`。方案的步骤尽量和现状一步对一步。细节（命令、数据行、提交号）放进 `details`，读者点开看，说明文字一两句。

## 写正文的规矩

- **每个专业术语、外部产品、组织名、编程语言和文件名，第一次出现时都加链接**，学习页里这是硬性要求，漏链和数字写错一样算错。只链官方或权威来源：
  - 机器学习概念：[Google 机器学习术语表](https://developers.google.com/machine-learning/glossary?hl=zh-cn)（中文版，锚点如 `#neural-network`）。
  - NLP 概念：[Hugging Face LLM 课程](https://huggingface.co/learn/llm-course/zh-CN/chapter1/1)中文版。
  - 库、模型、工具：官网、官方文档或官方仓库；论文链 arXiv 摘要页。
  - 公司或组织（Hugging Face、Google）链官网；编程语言（Rust、Python）链官网，有中文版就用中文版。
  - 不链博客、教程、问答和镜像。写进页面前先确认链接能打开、锚点存在。
  - 仓库里的文件用相对路径链接，例如 `../src/train.py`；正文里提到的文件名（tokenizer.json）也算。本地打开页面时，点击会在 VS Code 里打开这个文件。
  - 正文说本项目做了某件事（「MiniMind 用它训练分词器」）时，把这件事的字眼链到做它的源码。
- **数据必须真实**：录不到的环节（本机没有模型权重、连不上服务器）用最接近的真实数据代替，并在演示旁的说明文字里写明。比如 MiniMind 本地没有权重，解码那一步直接用编码得到的同一串编号。
- **说明文字里的结论要在代码格子的真实输出里有证据**：正文说「一来一回一个字都不丢」，代码格子就把整串解码的结果（`tok.decode(ids)`）打出来；Out 里看不到的结论就删掉。
- **代码格子只有两种**：给紧挨在它上面的演示配套，或者本身就是这一节要讲的内容。配套的格子紧跟演示，中间不放文字；代码按演示的几部分分段，每段上方单独一行注释（不写行尾注释，汉字占两格宽会对不齐）；Out 里要能找到演示用到的每个数字。
- **代码格子前后不写引导语和预告**：不写「演示里的数据来自真实运行，可以这样复现」，也不写「后面几节会讲」。别的小节要用某个 Out 里的数字就自己写出来，不往回引用。
- **不写操作提示**：正文和演示说明里不写点哪里、怎么翻页、悬停看什么、点开有什么，读者自己会用页面。
- **同类的几条信息写成列表**，不要串成一句。
- **代码格子标上语言**：`<pre class="code-in" data-lang="python">`，打包时用 [Shiki](https://shiki.style) 上色。Out 写真实运行结果。
- **输出是一张表时不贴对齐好的文本**：命令行按字符数补空格对齐列，浏览器里一个汉字占两格，列就歪了；值里有换行会把一行拆散，长值会冲出右边。让命令打印 JSON（`--json`、`-o json`、`--format json`），没有这个选项就让格子的脚本通过命令背后的接口或库取同样的行打印成 JSON；Out 写成 `<div class="code-out out-table"><table>`，一个值一格，原样转义，值里的换行保留。

## 加一个新知识点

1. 新建 `src/topics/<名字>/`，学习页照 `example/notebook.html`、改造页照 `example-change/notebook.html` 写正文。格子有三种：
   - `<section class="cell text">`：文字，`<h2>` 是一节标题，`<h3>` 是节内小标题，都会进左侧目录。
   - `<section class="cell code">`：代码，In 和 Out 各一个 `<pre>`；输出是一张表时 Out 换成 `<div class="code-out out-table"><table>`。
   - `<section class="cell demo" data-scene="名字">`：3D 演示，`名字` 对应 `main.js` 里注册的演示。

   文字格子里还能放两种排版，样式在 `notebook.css`：
   - `<svg class="diagram">`：手写的结构图，方框用 `box`，本项目用到的加 `used`，可选的加 `optional`，连线用 `edge`。
   - `<div class="cards">`：一组并列的卡片，每张卡片里的 `<ul>` 一行一个名字加解释，本项目用的那行加 `pick`。
2. 在 `main.js` 里调用 `startNotebook({ 名字: { name, tagline, steps, createView } })`：
   - `steps`：每一步的画面数据和说明文字（`phase`、`title`、`text`）。`phase` 决定说明栏左边小标签的颜色，新阶段名要在这一页的 `topic.css` 里配一个颜色。
   - `createView`：返回一个画面，提供 `mount(stage)`、`render(step, { reset })`、`setActive(active)` 三个方法。现成的有两种，见下一节。
3. 在 `viz` 目录运行 `pnpm build`，生成 `<名字>.html`；只想重建某几页时运行 `node build.mjs <名字>`，别的页面不动。

## 两种 3D 画面

- **数据流转图** `createFlowView(FLOW)`（`flow-3d.js`）：讲一份数据经过几个环节变成另一份数据，比如文字进分词器、编号进模型再回来。`FLOW` 是整段演示共用的布局：
  - `plates`：环节，像流程图的节点一样从左往右排成一行；
  - `slots`：方块排队的位置，每个 slot 一行，`label` 是行左边的名字，`alignWith` 让这行第 i 块对准另一行第 i 块，查表的结果和表里的行上下对齐，一一对应一眼可见；
  - `arrows`：平台之间地面上的箭头，沿深度 `z` 走，两个方向各走一排。

  分阶段的过程（先训练、再使用）画成前后两排：后排训练、前排使用，两排共用的规则和词表放在一块跨两排的平台上，训练往里写、使用从里面读。每块平台都写标题；第一行方块离平台后沿至少 1.5，不压住标题。中间产物（训练记下的规则）要作为方块出现在平台上，不能只写在说明里。示例的「拆分与合并」就是这样画的。

  每一步给 `blocks`（`{ id, text, tag, at, from }`，`at` 是 slot 名；方块的 `id` 整段演示不变，`from` 让新块从来源长出来，只有真正并成一块的来源才飞进新块）、`plates`（点亮的平台）、`arrows`（点亮的箭头，上面有点在流动）。词表只画这次用到的几行，按方块的顺序排。镜头按所有平台的范围和画面宽高比自动取景，不用手调坐标。

  组件图只能点亮「谁连着谁」，画面上看不到数据；要讲「什么变成了什么」（同一张词表，编码正着查、解码反着查）就用数据流转图。
- **组件图** `createGraphView(GRAPH)`（`graph-3d.js`）：讲一个系统里几个组件怎么互相调用、读写、引用，而且每一步动的组件不同。`GRAPH` 是整页共用的一张图，`groups` 是地面上的平台，`nodes` 是组件（`kind` 取 `process`、`store`、`table`、`ref`，要别的种类在 `GRAPH.kinds` 里补），`edges` 是连线（`dashed` 画成虚线，表示引用）。每一步给：
  - `nodes`：点亮哪些组件，状态是 `active`、`new`、`gap`、`base`、`off`，没列出的变暗；
  - `edges`：点亮哪些连线，可带 `label` 和 `tone`，点亮的连线上有点在流动；
  - `badges`：名牌第三行挂的数据；`details`：悬停和点开时看到的几行数据；
  - `focus`：镜头要看全的组件。

  悬停组件看说明和前四行数据，点击固定一个面板看全部，双击把镜头拉回这一步。组件图的名牌多，演示格子写成 `<section class="cell demo" data-scene="名字" style="--stage-height: 560px">` 加高画面。

  学习页的「核心概念」也用组件图画，叫概念图：一个核心概念一个组件，`sub` 写真实数字，连线标出关系（学出 token、按顺序套用）。组件写 `href`（讲它的那一节的 `#id`），点开的面板里就多一个「去讲它的那一节 →」链接。第 1 步看全貌（所有组件 `base`，`focus` 全部），之后按章节顺序一块块点亮，说明末尾写 `→ <a href="#章节">名字</a>`；格子高度用 600px。镜头只按组件取景，分组平台别比组件宽出太多，否则标题出画。

  第三方库的组件地图也用组件图画（参考 MiniMind 的 `library-map.js`）：一块平台标组件挂在哪个类上（`Tokenizer`），第一排按顺序是编码流水线（AddedToken → Normalizer → PreTokenizer → Model → PostProcessor），第二排是 Decoder；平台外左边是输入的文字、右边是 Encoding、左下是解码出的文字；后排放训练（语料 → Trainer → Model）和文件（tokenizer.json）两块平台。名牌第一行写类名，第二行写模块加「必须」或「可选」（`models · 必须`），说明写它管什么、常用的几个实现；`href` 指向讲它的那一章，没有专门一章的不写。步骤依次是总览、用本项目真实编码一句话走一遍编码流水线（每站挂真实中间结果，没设的组件挂「没设」并变暗）、两个可选组件（用用到它们的官方模型真实跑，链官方 API 锚点）、训练、解码、存成文件，每步说明末尾链到讲它的那一章。

  分组标题沿平台后沿摆放，后沿和第一排组件之间至少留 3（`node.z ≥ group.z − group.d / 2 + 3`），不然名牌立起来会挡住标题。

步骤数据算和画分开：一个纯计算函数产出每一轮的记录，各个画面的函数把同一份记录画成自己的步骤。同类演示再共用一个布局函数（比如 `trainEncodeFlow(...)`），slot 和箭头的名字统一。

几站排成一条直线时（预分词、解码器、tokenizer.json 的存取），用 `pipeline-flow.js` 的 `pipelineFlow({ stages, rows, arrows, labels })` 生成 `FLOW`：平台从左到右排开，每站可以有不同的行数，slot 名是「平台 id + 行号」（如 `letters0`），箭头 id 是 `from>to`，标题前留好位置，颜色按顺序轮换。后面的步骤留着前面站点的方块，下一站的方块从它们长出来，放到最后一步整条链都还在。

示例页 `example.html` 两种都有：三段数据流转图（简介、预分词、拆分与合并）和组件图讲同一次计算，概念图也用组件图画。要写新的方块类画面时，在 `blocks-3d.js` 的 `createBlockScene` 上搭，不要复制舞台、镜头和过渡动画。

## 真实运行录制

讲的是一个系统随操作变化的状态时（同步进程、Git 服务器、数据库），录一次真实运行，代码格子的 Out、正文里的数字和 3D 演示都从这一次运行里取，三者不会对不上：

```
runs/
├── demo.py             演示环境：包装被测代码执行命令用的执行器（沙箱类、subprocess.run），
│                       把每条命令和输出记进日志；frame(名字) 把那一刻的系统状态和这段时间的命令存成一帧
├── c*.py               每个代码格子的 In，按 run_all.sh 里的顺序接着跑
├── run_all.sh          按顺序重跑全部格子，把输出和帧拷进 out/
├── out/                每格的真实输出、全部帧、运行时存下的值
├── notebook.tpl.html   正文模板：代码格子写成 <!--CELL:名字-->，运行得出的值写成 {{sha:名字}}
└── fill_cells.py       In、Out 原文只做 HTML 转义填进模板，Out 是 JSON 行时排成表格，生成 notebook.html；帧写成 trace.js 给 steps.js 用
```
