# Clash 最佳实践

当前只包含「家宽出口配置」。以后按主题扩展，不把一次任务的地址、凭据和临时文件写成通用规则。

## 不可跳过的约束

- 保护当前会话和远程管理连接；先独立验证，再应用。用户要合并配置不等于允许重启代理、开关虚拟网卡或改浏览器、语言、时区。
- 不因截图来自开发环境就改仓库；先识别是在修本机网络。
- 读取现状，备份原文件和当前选择；不知道正在生效的配置就不能热更新。
- 只保留用户要用的一条家宽出口；多个候选先测试，不默认全部导入或自动切换。
- 密码、订阅链接、控制接口令牌只在本机受保护文件或进程内处理，不进日志、技能、仓库或外部报告。临时目录权限 700，含凭据文件 600。

## 1. 建立基线并保护会话

记录客户端和内核版本、当前订阅、节点选择、系统代理、虚拟网卡、DNS、规则和相关增强脚本。当前运行状态、界面内存、磁盘文件可能不一致。

查明当前聊天或管理服务的实际地址及正确通路，不读取无关凭据。若已验证该地址直连正常、经过新代理失败，应在规则最前面保留精确直连规则；不要让它落入兜底代理：

```yaml
rules:
  - IP-CIDR,192.0.2.20/32,DIRECT,no-resolve
```

这里是文档示例地址，必须替换成已获授权、已验证的目标。域名使用精确域名规则；不要扩大为整段网络直连。

首页返回 200 仅证明该请求可达，不等于聊天接口及长连接正常。分别验证实际服务所需的握手、重复请求和连接保持；未测到的明确写“未验证”。

## 2. 先判断家宽是否需要中转

当前电脑开着虚拟网卡时，普通请求和直接指定 SOCKS 的测试也可能借道旧节点。`--noproxy '*'` 只绕过显式代理，不绕过虚拟网卡。

另起独立 Mihomo：仅在新测试实例中设置 `tun.enable: false`，不改现用实例的虚拟网卡和系统代理；只监听本机空闲端口，使用单独数据目录。确认测试实例的出站使用实际物理网络，不会被现有代理再次接管。

分别测试“物理网络 → 家宽”和“稳定中转节点 → 家宽”。如果只有后者通过，正式配置必须保留同一中转：

```yaml
proxies:
  - name: Residential
    type: socks5
    server: 192.0.2.10
    port: 443
    username: REPLACE_LOCALLY
    password: REPLACE_LOCALLY
    dialer-proxy: STABLE_RELAY_NODE
```

这是结构示例，不可直接导入。中转节点必须真实存在，且不能引用最终又选回 Residential 的分组，避免循环。

443 端口不代表加密。普通 SOCKS5 的认证并非端到端加密；中转协议的加密也不自动覆盖“中转 → 家宽”这一段。需要服务商支持的加密方案，不能擅自添加 TLS 选项假装加密。

## 3. 分流与 DNS 配套

国外代理网站：域名查询通过已验证的代理走加密 DNS。
国内直连网站：通过 `direct-nameserver` 获取适合本地访问的地址。

```yaml
dns:
  enable: true
  respect-rules: false
  nameserver:
    - 'https://1.1.1.1/dns-query#Residential'
    - 'https://8.8.8.8/dns-query#Residential'
  direct-nameserver:
    - 'https://223.5.5.5/dns-query#DIRECT'
  direct-nameserver-follow-policy: false
```

此例只适用于用户需要国内直连的场景。保留必要的局域网、企业及 VPN 域名策略。检查继承的 nameserver-policy、fallback、系统 DNS 等是否另有解析通道，不盲目清空所有策略。

`proxy-server-nameserver` 用于解析代理服务器地址，不能依赖尚未解析出的同一代理。优先使用已知 IP 的稳定中转，或设计独立且已验证的启动解析路径。

国内域名走了国外 DNS，可能得到海外地址：即使规则是 DIRECT，网站仍会慢或打不开。先核对命中规则和解析地址，不靠逐个网站补丁解决。

## 4. 区分 IPv4、IPv6、UDP 与检测标签

- IPv4 和 IPv6 出口不同，只能证明出口不同；不能直接断言 IPv6 绕过代理。检查目标域名命中的组、连接记录和完整代理链。
- `curl -4/-6 --proxy http://127.0.0.1:端口` 不证明目标使用哪种地址：目标可能由代理解析。用只提供对应地址族的测试目标，结合实际出口和代理连接记录验证。
- SOCKS 的 TCP 登录成功不代表 UDP 能用。用真实 UDP 请求或浏览器连接测试；看不到公网候选也可能是 UDP 不通，不等于支持正常。
- 不随意切换 udp 选项。某些规则路径在节点不支持 UDP 时可能继续匹配其他规则；必须验证失败时不会直连泄漏，同时说明视频、游戏等功能限制。
- 家宽、ISP、机房是第三方资料标签，不是协议属性。先比较同一目标的完整出口 IP、地址族和数据源；不能仅凭运营商名称断言家宽或机房。DNS 服务器与出口不属于同一家公司并不等于泄漏。

## 5. 验证通过后再应用

1. 用当前版本的真实内核检查完整候选配置，包括分组引用、规则顺序和循环依赖。语法检查不等于可用性测试。
2. 在独立端口验证会话地址、国内网站、国外网站、实际出口和 DNS；连续测多轮。依赖远程规则集时还要验证文件下载成功、规则数量及代表性命中；不能只有空分组和兜底规则。
3. 做可脱离当前聊天运行的失败恢复：备份可用配置，恢复原节点选择；处理失败、超时和常规终止。实际演练恢复，不能只写一个“自动恢复”提示。
4. 只在线应用已验证内容，保持用户当前代理和虚拟网卡开关。JSON 内嵌配置必须正确保留中文及 emoji；Python 用 `json.dumps(config, ensure_ascii=False)`。
5. 应用后重新跑会话、国内外和泄漏检查，再确认保留；失败恢复旧配置。取消或中断后重新查状态，不把中断当成功。使用用户本机浏览器验证，远程抓取服务测不到用户网络。

若失败恢复依赖单一后台进程，进程被强杀或终端退出就可能失效；不能声称有可靠自动恢复。没有经过验证的独立恢复措施时，不进行可能切断唯一控制通路的变更。

## 6. 持久化、合并和手机导出

原始订阅 + 客户端增强脚本/覆写 → 最终运行配置。三者不能混为一份文件。

- 合并时明确节点来源及规则来源。新增节点、中转引用、分组默认选择、精确会话直连和国内 DNS 策略都要保留；不要只复制 rules 而丢掉 rule-providers 和分组。
- 使用真正的 YAML 解析器，不用逐行截取解析节点；内联 YAML 会把账号密码一起误当节点名输出。规则条数不代表覆盖范围，一个 RULE-SET 可包含大量规则。
- 不直接修改会被订阅刷新覆盖的原始下载文件。把本地节点和策略放入客户端支持的增强机制，分清动态规则更新与一次性快照。
- 核心接口切换节点不保证界面保存选择。以实测版本为准，通过客户端支持的保存和重新生成流程同步；不要在应用运行时直接改它已缓存的 profiles.yaml。
- 手机要导出增强处理后的完整 YAML，不能交付原始订阅或电脑 JavaScript。使用最新状态生成，不拿旧临时文件当最终版本。
- 手机文件保留家宽、中转、分组、DNS、规则和规则集；清理桌面 Unix socket、绝对路径、物理网卡名及本机专属控制设置。虚拟网卡等平台项按手机客户端文档处理，不能一律照搬或关闭。
- 导出前检查分组引用、路径、远程规则集可获取性，并校验文件。桌面验证通过不等于手机已验证，导入后还需核对节点、分组、出口和国内直连。文件含私密凭据，只交付用户，不公开上传。

## 工具与结论要求

查库、客户端或 CLI 配置先查 Context7 与对应版本官方文档。使用 `uv run --no-project python -I` 运行诊断脚本；添加依赖使用包管理命令，不改当前业务仓库。优先结构化读取，输出前脱敏。

第三方“风险百分比”不是已校准的封号概率，不为刷分修改系统或检测页面。结论只写实际验证结果：哪些流量走哪条通路、测试是否完成、是否已保存、手机是否已验收。
