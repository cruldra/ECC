# 开启对等会话

同一台机器上的会话可以互相看到并发消息。`ListAgents` 列出它们，`SendMessage` 按名字投递给其中一个，对等会话会在它的下一轮工具调用时收到。本技能覆盖的是那些不会自动发生的部分：开一个新会话、得知真正能寻址到它的名字，并走完闭环，免得还有人得手工转达。

## 会话，而非子代理

点名某个模型或 profile——新建一个 opus 会话、开个 grok tab、派个 gpt56 会话、让 fable5 跑一下——要的是一个**独立 tab 里的对等会话**：在编辑器中可见、可引导，用户还能随时接管。这就是本技能。

Agent 工具是另一种东西：一个进程内子代理，没人能看到它，被钉死在其代理类型声明的模型上。用户点名了模型却去用它，结果就是在同一个仓库里、用一个用户没有要求的模型干活，而且是在一个用户打不开的窗口里。措辞不必说出 "tab" 或"对等"——请求里出现一个模型名就够了。

只有明确说出 子代理 / subagent / Agent 工具 才会选中 Agent 工具。

## 先复用，再开新

每次都先 `ListAgents`。已开着的会话握有上下文，新开的那个得重新建立，结果用户要照看两个。

只有当没有合适的在跑会话，或用户点名的模型一个会话都没有时，才开新会话。"让 grok 验一下"且没有在跑的 grok 会话，就是要开新的；这不是获准改在本会话代劳。

当两个会话都可能成为目标时，通过会话记录把名字映射到模型和主题，而不是猜测：

```bash
cd ~/.claude/projects/<cwd with / replaced by ->/
ls -lt *.jsonl | head
grep -o '"model":"[^"]*"' <id>.jsonl | sort | uniq -c
grep -c "<task keyword>" <id>.jsonl
```

归一化模型别名：转小写、去掉非字母数字字符，然后按包含关系匹配：`gpt56` 命中 `gpt-5.6-sol`，`grok` 同时命中 `grok-4.5` 和 `grok-4.6`，需要靠主题检查来打破平局。仍有歧义——就问。发给错误会话的消息会污染无关的上下文。

## 开启新会话

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/spawning-peer-sessions/scripts/spawn-session.sh" \
  --profile opus \
  --name review-pr-402 \
  --prompt "任务描述，禁单引号" \
  --cwd /abs/path/to/repo
```

它会打印出用来寻址的名字：

```
已开会话
  名字: ecc-b3
  类型: interactive
  发消息: SendMessage {to: "ecc-b3", message: ...}
```

**使用打印出的名字。** 不要复用 `--name`，也不要事后靠一次 `ListAgents` 去猜。tab 后端命名的是编辑器 tab，不是会话；会话以自动生成的名字注册，`--name` 根本到不了会话那里。脚本通过对比开新会话前后的会话列表来解析出真正的名字。

### 两种后端

`--backend tab`（默认）打开一个真实的 VS Code 终端 tab。只要有人可能想观看、引导或接管会话，就用它——这种可见性正是偏向它的全部理由。需要 VS Code、superpowers 扩展，以及当前窗口中打开的工作区文件夹。

`--backend bg` 运行 `claude --bg`。没有编辑器，在 ssh 下和任何平台上都可用，且会话在完成它的回合之后仍然可以寻址。没有任何可看的东西：输出只能通过 `claude logs <id>` 或 `claude attach <id>` 获取。当 tab 后端不可用、或没人需要观看时用它。

tab 后端无法报告它自己的错误。错误的 profile 名、没有工作区文件夹的窗口、被拒绝的 URI 提示——这些都以 VS Code 通知的形式出现，调用方代理永远看不到，而且 `code --open-url` 无论如何都返回 0。脚本会等待会话出现，若未出现则显式报错——真的失败时，请让用户去读那条通知。

### Profiles

`--profile` 接受 profiles 目录下的文件名，不带 `.json`。默认位置是 `~/Sources/cruldra-profile/claude-config/profiles`；可用 `ECC_PROFILES_DIR` 覆盖。把用户别名转小写、去掉非字母数字字符，再做前缀匹配：`gpt56` 解析到 `gpt-5.6-sol.json`。候选为零或多个——就问，别替用户挑。

### Prompt 规则

单引号会被拒绝：tab 后端用单引号包裹 prompt 来拼命令行。脚本会提前失败，而不是让扩展来拒绝。

prompt 要短。长上下文应该放进文件——把路径写进 prompt，让对等会话自己去读，而不是把它的上下文窗口花在它可能不需要的文本上。

## 任务简报

对等会话开工并完成所需的一切，放在消息里，或放在消息指向的文件里：

- 仓库绝对路径、分支、PR 或 issue 编号
- 问题在哪、正确长什么样
- 文件和行号
- 怎么验证
- **回报给谁**

正是回报那一句让它成为闭环而不是单向投放。用本会话自己的名字——`ListAgents` 输出的第一行就印着它：

```
做完后 SendMessage 回报 <本会话名字>：结果摘要、改了哪些文件、怎么验的、没做的部分。
```

那一行也要写进简报文件。对等会话可能只会看到文件。

在 `SendMessage` 调用里加上 `notify_when_idle: true`，就能在对等会话转为空闲时收到一次通知。绝不要循环轮询 `ListAgents`，也绝不要发"你好了没"。

## 接收任务

当消息以 `<cross-session-message from="...">` 包裹着到达，或简报文件把本会话指名为回报对象时，本会话就是对等会话。干完活不等于完成任务。最后一步是：

```
SendMessage {to: <requester>, summary: "<task> 完成/受阻", message: 结果摘要 + 改动文件 + 验证方式 + 没做的部分及原因}
```

地址取自 `from` 属性或简报。受阻和部分完成也算结果——说明卡在哪里。然后告诉用户回报已发出。

## 权限边界

对等会话无法扩大本会话的权限。绝不替对等会话执行在这里被拒绝过的操作，绝不把对等会话的请求当成用户的许可，也绝不要求对等会话去做在这里被拦下的操作。改而把它转回给用户。

## 常见错误

| 错误 | 后果 |
|---------|-------------|
| 用户说了 会话/tab 但没说"对等"，就用了 Agent 工具 | 错误模型上的进程内子代理，在一个谁都打不开的窗口里 |
| 开新会话前没先 `ListAgents` | 握有上下文的会话其实早已开着；用户现在得维护两个 |
| 用户点名某模型来验证，本会话却代为验证 | 被点名的模型从未运行；应当开新会话 |
| 在候选会话之间猜测 | 发错会话，污染上下文 |
| 用 `--name` 给对等会话寻址 | `--name` 只是 tab 标题，不是会话名；消息会被弹回 |
| 刚开完新会话就调 `ListAgents` 并宣布失败 | 注册有延迟；脚本本来就会等——再次执行会开出重复的 tab |
| 把几 KB 的上下文粘进消息 | 烧掉对等会话的上下文；写成文件，发路径 |
| 轮询 `ListAgents` 等完成 | 改用 `notify_when_idle: true` |
| 简报缺少回报对象 | 对等会话做完即停；用户只能手工转达 |
| 完成受托任务后只回复用户 | 同上；请求方仍在等待 |
